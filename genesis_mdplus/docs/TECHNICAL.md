# Technical notes

| File | Role |

## MD+

68000 side (as on MegaSD):

| Address | Access | Meaning |
| --- | --- | --- |
| `$3F7FA` | write `$CD54` / `$0000` | open / close the command window |
| `$3F7FE` | write | command |
| `$3F7FC` | read | status (bit 0 = playing) |

Commands: `11NN` play once, `12NN` play loop, `1300` stop, `13FF` fade/pause,
`14xx` resume, `15xx` volume. Internal (save state load only): `1ANN` / `1BNN`
play once / loop from a given byte position.

Start-up (clk_74a, `mdp_core`)
1. `0x0190` gets the ROM path from slot 0; the extension is replaced by `.cue`.
2. `0x0192` opens it in slot 20, `0x0180` reads it into PSRAM, the cue is parsed
   into the track table (`FILE`, `TRACK`, `REM LOOP n`, `REM NOLOOP`).
3. Each wav is opened in slot 21 (player) or 22 (background cache) the first
   time it is needed; its header is scanned for the `data` chunk.

PSRAM
- PSRAM 0: track head cache, 64 slots x 256 KB; slot 63 holds the save state.
- PSRAM 1: 4 MB streaming ring, header scratch (0x800000), cue (0x900000),
  track table (0xA00000, 16 bytes per track).

Audio: 44.1 kHz -> 48 kHz (phase accumulator 147/160, linear interpolation),
fades, MD+ volume and menu volume, mixed with the console audio.

## Save states

Bridge window `0x50000000`, size `0x24800` bytes (big endian 32-bit words, two
16-bit stream words each).

Capture
1. The Pocket sends `0x00A0`; the request is passed to clk_sys.
2. On the next level 6 interrupt acknowledge, the vector read at `$78` (after
   the PC/SR stack writes) returns `$5F0000` (save) or `$5F01A0` (load).
3. The routine at `$5F0000` (overlay, only while active) streams the state
   through a port at `$5FE000` into PSRAM 0 slot 63:

| Stream word | Content |
| --- | --- |
| `0x0000` | D0-D7/A0-A6, USP, SSP |
| `0x0040` | info block (128 words): Z80 registers and state, Z80 bank, mapper banks, MD+ track/position, YM2612 key state, VDP registers, PSG restore bytes |
| `0x00C0` | YM2612 register shadow (512 bytes) |
| `0x01C0` | CRAM (64 words) |
| `0x0200` | VSRAM (40 words) |
| `0x0240` | I/O port data / control |
| `0x0400` | Z80 RAM (8 KB, one byte per word) |
| `0x2400` | VRAM (64 KB) |
| `0xA400` | 68000 RAM (64 KB) |

4. It waits for the start of the next vblank and `STOP`s; that interrupt is
   redirected to a stub at `$5F03D0` that drops its frame and jumps to the
   game's own vblank handler with the saved frame, so the game continues
   exactly where it was.

Write-only registers are snooped from bus writes (VDP registers, PSG latch,
YM2612 address/data and key on). The Z80 is stopped by gating its clock enable
at the start of an M1 cycle (away from its interrupt); a halted Z80 restarts on
its `HALT`. Its registers are read from T80 `REG` and loaded through `DIR`.

Load: the blob is written by the Pocket (before or after `0x00A4`), checked
(magic `MS` at stream word `0x40`), then the routine at `$5F01A0` restores RAMs
and VDP memories (display off), YM2612 registers are replayed by hardware
(frequency MSB registers first), Z80 registers are loaded, VDP/PSG registers and
CPU registers are restored, and the MD+ track is restarted at the saved
position.
