# 개발 일지: Analogue Pocket SNES 코어(agg23 openFPGA)에 MSU-1 추가

작성일: 2026-11-03 (진행 중인 작업 포함)

## 1. 목표

- agg23의 Analogue Pocket용 SNES 코어(openfpga-SNES 0.4.4)에 **MSU-1**(CD급 PCM 음악 + 대용량 데이터 스트리밍)을 추가한다.
- MiSTer SNES 코어(SNES_MiSTer 1.2.0)를 참고 구현으로 삼는다.
- 최종 결과물: Pocket에서 바로 실행되는 코어 폴더(.rev 비트스트림 포함)를 **배포용 ZIP**으로 제공한다.
- 첫 목표는 1GB 미만 MSU-1 팩(예: Tales of Phantasia, FF6 MSU 팩)이다.
- 가능한 칩은 한 코어에 합치고, 완성되면 디버그용 비프음은 제거한다.

## 2. 개발 환경

- 빌드: PC의 Quartus Prime 25.1 Lite (`quartus_sh -t generate.tcl <variant>`)를 사용한다.
- 대상 FPGA: Cyclone V 5CEBA4F23C8 (18,480 ALM, 308 M10K).
- 비트스트림 변환: `ap_core.rbf`를 비트 반전해 `.rev`로 만든다(`tools/rbf_to_rev.py`). 변환 후 997바이트마다 샘플링해 검증한다.
- 빌드 한 번에 약 20분이 걸린다.

## 3. MSU-1 구현 요약

- 상류(openfpga-snes 0.4.4)에 이미 있던 MiSTer 유래 MSU-1 HDL(레지스터 $2000–$2007 포함)을 켜고 Pocket에 연결·수정했다. 파일은 `<rom>.msu`와 `<rom>-N.pcm`을 쓴다.
- PCM 형식: 헤더 "MSU1", 루프 지점(u32), 16-bit LE 스테레오 44.1 kHz.
- 0바이트 `.msu` 파일도 크기 폴백으로 동작한다.
- 오디오 경로(`msu_audio.v`)는 청크 8192 B / 리필 레벨 2048 B로 읽고, 정렬된 읽기와 재시도 로직을 넣었다.
- 디버그 비프 코드(진단음)를 넣어 상태를 소리로 확인하며 개발했다. 예: PCM 파일이 없으면 4번 울린다.

## 4. 코어 구성과 용량(Fit) 실측

특수칩은 FPGA 면적 때문에 구성별로 나눠서 빌드했다.

| 빌드 | 구성 | ALM | RAM 블록 | 타이밍 |
|---|---|---|---|---|
| NTSC 메인 | CX4 + GSU + DSPn + S-DD1 + MSU | 약 92% (16,943) | 94% (291) | slack +0.102 |
| PAL 메인 | 위와 동일(PAL PLL) | 약 92% | 94% | slack +0.077 |
| SA-1 | SA-1 + MSU | 76% | 78% | Fast-0C hold −0.016 |
| SPC7110/BSX | SPC7110 + BSX + S-DD1 + MSU | 92% | 80% | — |

- 면적 추정(ALM): 기본 코어+MSU 약 11.3k, S-DD1 약 870, SPC7110 약 4,260, BSX 약 480, SA-1 약 2,600, CX4+GSU+DSPn 약 4,700.
- Tales of Phantasia는 ExHiROM이고 코프로세서가 없다. 그래서 S-DD1 없이 메인 코어로 충분하다.
- S-DD1을 메인 코어에 합쳐도 용량에 들어가는 것을 확인했다.

## 5. 해결한 문제들

1. **디버그 비프음 제거**: `BEEP_ENABLE=0`으로 껐다. v17에서는 PC에 소스가 반영되지 않아 비프음이 남은 채 배포됐고, v18에서 4종 비트스트림 모두 제거했다.
2. **파일 전송 문제**: 이미 있는 PC 경로에 덮어쓸 때 예전 내용이 남는 현상이 있었다. 새 디렉터리나 새 파일명으로 보내고, 다시 읽어서 확인하는 절차로 바꿨다.
3. **빌드 경로 오류**: 배치 파일의 Quartus 경로가 틀렸던 것을 바로잡았다.
4. **CPU Turbo로 게임이 멈추는 문제**: 원본 터보는 주변장치 접근이 없는 구간에서 5 마스터 클럭 사이클(약 4.3 MHz)로 동작한다. 먼저 6클럭(FastROM 속도)으로 완화한 v18을 냈다. 아직 하드웨어 테스트 결과를 받지 못했다. 원인은 확정되지 않았고, 메모리 응답이 5클럭에 맞지 않을 가능성을 의심하고 있다.
5. **정정한 오해**: 터보 수치를 "4→5 클럭"이라고 설명했는데 실제로는 마스터 클럭 기준 5→6이었다. 터보가 막히는 칩은 DSPn이 아니라 SA-1과 S-DD1이다.

## 6. 현재 작업

- **3단계 터보**를 구현했다. Off / On(6클럭, FastROM 속도) / Max(원본 5클럭). `CPU.vhd`, `SNES.vhd`, `main.v`, `SNES.sv`, `core_top.sv`와 `interact.json`(리스트 옵션)을 수정했다.
- **CX4와 DSPn을 뺀 통합 코어**: SA-1 + GSU + S-DD1 + MSU를 NTSC/PAL 한 코어로 만든다. 추정 약 90%이며, 빌드로 용량을 확인하는 중이다.
- 빌드 순서: SA-1+GSU+S-DD1 NTSC, PAL, 이전 구성(CX4+DSPn 포함) 메인, SPC7110/BSX 순이다.
- 완료되면 용량·타이밍을 확인하고 `.rev`로 변환한 뒤 ZIP으로 전달한다.
