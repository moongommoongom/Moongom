# Moongom SNES MSU-1 0.8.5 — technical notes

0.8.5 is the improved 0.8 (`Moongom.SNES_MSU_SS`). Instead of the experimental save state core used by 0.8
(`snes_msu_ss/`), it is built on the R1 line in `src/` (agg23 openfpga-snes 0.4.4 + MSU-1), with the MiSTer SNES
save states ported in. The R1 audio path (MSU-1 mixer, DSP) is kept.

## 0.8.6 (bug fix)

- In-game saves were lost on `snes_main.rev`. The loader raises `ioctl_download` a second time for the `.sav` file
  (`ioctl_index` is always 0), so the RAM clear also runs while the save is written into the cart RAM. The clear
  sweeps 2^17 addresses; with the 32 KB cart RAM of the `ss_main` build it wrapped four times (about 24 ms) and filled
  a save that had already arrived with FF. `rtl/mister_top/SNES.sv` now fills the cart RAM only during the first pass
  over its own size and stops the fill as soon as save data arrives.
- Released: `snes_main.rev` rebuilt from this source; the other seven bitstreams are the 0.8.5 builds (128 KB cart RAM,
  not affected). Building them from this source adds the same guard.

## Save states

- MiSTer SNES save state hooks (upstream commits 7e9ec63 "Add Save states" and follow-ups) in CPU / PPU / SMP / DSP /
  SNES, the MiSTer `savestates*.sv` engine, the Pocket blob controller (`mister_top/savestate.sv`,
  `psram_blob.sv`, `savestate_controller.sv`) on cram1, bridge region 0x7, `sleep_supported: true`.
- Coprocessors: only the save state parts of the upstream chip commits were merged into the R1 chip files (three-way
  merge, base = upstream parent commit), so the chip behaviour stays R1:
  - SA-1 (7e9ec63; the R1 SA-1 has no BW-RAM / I-RAM write protection, those registers read back as 0),
  - Super FX (7e9ec63, without the later FASTROM / ROM address latch changes),
  - DSP-n (7e9ec63 + fac74ae), DSP_LHRomMap (7e9ec63, plus a `USE_SRTC` switch),
  - CX4 (777ca96 without the 85b76d3 ROM address latch).
- S-DD1: registers $4800/$4804-$4807 are read and written back by the 0.8 firmware block $18.
- SPC7110 (experimental, new in 0.8.5): firmware block $1A saves 37 registers ($4801-$4806, $4809-$480C,
  $4811-$4818, $4820-$482E, $4830-$4833). While `SS_BUSY` the SPC7110 accepts these writes without side effects
  (no decompression start, no pointer adjust, no ALU run, result registers writable, ALU inputs readable) and its data
  ROM fetch engine is frozen; after the load it refetches the data port byte. The decompressor state is not saved:
  a state saved in the middle of a decompression stream can show broken graphics after a load.
  BS-X and OBC1 carts have no save states.
- Save state firmware: `src/fpga/core/rtl/mister_top/boot1.mif`, built by `tools/boot1/mkboot1.py` from the 0.8
  firmware `snes_msu_ss/rtl/upstream/releases/boot1.rom`.

## MSU-1

- Music and voice streams (`.msp` / `.ms1` packs) have PSRAM stream caches on cram1 (`msu_scache.v`, `msu_pr_arb.v`):
  the SD card has one command channel with a large per-request latency, so both streams read ahead in large chunks
  (round robin, a voice clip start has priority, music read-ahead limit, 256 KB first voice read).
- The cache arbiter is held while the save state controller moves the blob (otherwise blob staging was lost and loads
  were refused while MSU-1 streamed).
- Save states store the music track, play position (64 KB steps, about 0.37 s), volume and repeat flag through the
  shadow window $2008-$200F (firmware block $19); a load selects the track again and resumes at the saved position.
  A voice clip is stopped by a load.
- Voice window $2010-$2017 (FF6 voice packs, ROM patched for it).

## Bitstreams

The APF allows at most 8 bitstreams per core folder (file names at most 15 characters). The loader
(`src/support/loader.asm`; the release `loader.bin` is the openfpga-snes loader patched by
`tools/loader085/patch_loader.py`) picks one from the ROM header:

| # | File | `generate.tcl` variant | Contents |
|---|---|---|---|
| 0 | `snes_main.rev` | `ss_main` | NTSC: plain, S-DD1, BS-X, FF6 voice stream, light gun |
| 1 | `snes_spc.rev` | `v085_spc` | NTSC: SPC7110 (save states experimental) |
| 2 | `snes_pal.rev` | `ss_cx4dsp_pal` | PAL: plain, CX4, DSP-n |
| 3 | `snes_cx4dsp.rev` | `ss_cx4dsp` | NTSC: CX4, DSP-n |
| 4 | `snes_sa1.rev` | `ss_sa1` | NTSC: SA-1 |
| 5 | `snes_sa1p.rev` | `ss_sa1_pal` | PAL: SA-1 |
| 6 | `snes_gsu.rev` | `ss_gsu` | NTSC: Super FX |
| 7 | `snes_gsup.rev` | `ss_gsu_pal` | PAL: Super FX |

Coprocessor bitstreams (`SS_CHIP=1`): ARAM on the async SRAM, 128 KB cart RAM in BRAM, music fetched straight from the
bridge (no stream cache), no voice stream, no MSU-1 data track, no light gun, no S-RTC. All 8 meet timing
(Quartus 25.1 Lite, 84-99 % ALMs).

The released `snes_sa1.rev` was compiled from the source a few minutes before the `SS_CHIP` feature switches were fixed,
so it still contains the voice stream, light gun and music stream cache (99 % ALMs). Building `ss_sa1` from this
repository gives the leaner variant; both have the same SA-1 save states.

## Build

Quartus Prime 25.1 Lite, in the repository root: `quartus_sh -t generate.tcl <variant>` for each variant above, then
bit-reverse each `.rbf` to `.rev` (`tools/rbf_to_rev.py`). Package files: `pkg/pocket/Cores/Moongom.SNES_MSU_SS/`.
